# 小模型 LoRA 微调踩坑清单（10 条）

> 每一条都有本仓库的实测数据支撑，不是通用建议。
> 环境：MiniMind-3（64M）/ RX 7800 XT / WSL2 + ROCm 7.2 / transformers 4.57.6

| # | 坑 | 现象 | 教训 | 本仓库证据 |
|---|---|---|---|---|
| 1 | 用 loss 选超参 | r32 的训练 loss 最低（0.8429），输出却是英文碎片循环 | loss 只反映"拟合训练集"，不反映"能否生成" | §5.2 |
| 2 | 用"末步 loss"比较 | r8 从 196 步的 1.48 升到 294 步的 1.82，行为反而更接近目标 | 末步 loss 来自单个 batch，噪声极大；要看多 batch 平均或趋势 | §5.7 结论 14 |
| 3 | 同质数据 + 大容量 | 91 条英文身份样本 + rank32 → 英文模板过拟合，中文能力被挤掉 | 数据分布越窄，越要先减小容量（rank），而不是加步数 | §5.2 |
| 4 | 忽略"身份泛化" | r16 对「推荐中国美食」也回答「我是小澜」 | 小模型会把最高频答案当万能模板；定性检查必须包含**无关问题** | §5.6 |
| 5 | 低估底座先验 | 196 步后 r8 仍自称「由 jingyaogong 创建」 | 底座的身份先验很强，步数不够就覆盖不掉；要预留足够步数 | §5.6 → §5.7 |
| 6 | 用模板数据猛训 | 294 步后出现「一个小澜的中文小澜」「不是 AI，也不是人类，也不是人类」 | 重复退化随步数加重；**数据多样性 > 训练时长** | §5.7 |
| 7 | 认为 rank 越大越好 | rank 8→32：结构更贴近目标，但语义边界更差、更爱绕圈 | rank 提升的是"拟合能力"，不是"语义控制力" | §5.6 / §5.7 |
| 8 | 孤立看学习率 | r32 + lr1e-4 崩坏；lr 降到 5e-5 立刻稳定，但学不到目标 | lr 与 rank 是乘积关系，必须成对调；单独扫一个会得出错误结论 | §5.3 |
| 9 | 定性检查只用 1 个 prompt | 只看 `hi` 会误判 r32「能用」 | 至少 3 类 prompt：身份类、任务类、闲聊类，且温度固定 | §5.2 / §5.6 |
| 10 | 忽略硬件稳定性上限 | WSL 下约 400–500 步后 HSA 主机内存池耗尽，会话被终止 | 单进程步数要设上限；用 `--from_resume 1` 分块续训 + 更密的 `save_interval` | §6 |

## 一条元教训

上表 10 条里有 8 条是**"指标与目标不一致"**的变体：loss 不等于质量、参数量不等于能力、步数不等于学会。
小模型微调的主要工作量不是调参，而是**建立能识破这些不一致的检查手段**（多 prompt 定性检查、多 batch 平均、对照实验）。
